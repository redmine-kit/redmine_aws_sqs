# ジョブ

Redmine Kit AWS SQS は、環境変数 `REDMINE_SQS_QUEUE_URL` を設定すると、メールの送信、プロジェクトの削除、Webhook などの Redmine のバックグラウンドジョブを、1 つの Amazon SQS キューから実行します。設定しなければ、ジョブは Redmine の標準の方法で実行します。メッセージが何を指定していても、実行するのはプラグインが許可したジョブクラスだけです。最終的に失敗したジョブは記録し、再送信できるようにします。

「管理」›「AWS」›「ジョブ」には、キューと失敗したジョブを表示します。開けるのはシステム管理者だけで、このタブでの操作は Redmine のログに書きます。

## キュー

「利用可能なメッセージ」、「処理中のメッセージ」、「遅延メッセージ」と、「デッドレターキュー」のジョブの数です。最後に読み込んだときの値を表示します (右上の「更新: …」)。スケジュールで実行する rake タスク (`redmine_kit:aws:sqs:refresh`) が読み込み、「最新の情報に更新」ですぐに読み込み直します。デッドレターキューにジョブがあるあいだは、「DLQ 再処理を開始」で、それをジョブキューに戻せます。

## 失敗したジョブ

最終的に失敗した最近の 100 件のジョブを、すべて、または「メール」だけ、「ジョブ」、「エラー」のクラス、「試行回数」、「登録日時」、「失敗日時」とともに表示します。ジョブをチェックして、次の操作をします。

- 「再送信」: ジョブキューにもう一度送ります (キューを設定しているときだけ)。
- 「削除」: 記録を削除します。

`redmine_kit:aws:sqs:prune` は、90 日 (`DAYS` で変更) より前に失敗したジョブの記録を削除します。
